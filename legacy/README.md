# Legacy — 이전 구현 및 실험 기록

이 디렉터리는 CANOPY 프로젝트의 초기 구현, 이전 실험 결과, 현재 구조로 이관되지 않은 코드를 보존하기 위한 영역입니다.

프로젝트 개발 과정에서 데이터 처리, 머신러닝, 클라우드 및 애플리케이션 코드를 통합 모노레포 구조로 정리했습니다. 이 과정에서 이전 구현을 무조건 삭제하거나 이동하는 대신, 개발 이력과 의존성을 추적할 수 있도록 별도 영역에 보존했습니다.

## 디렉터리 구성

### `original-data-platform/`

CANOPY 초기 데이터 플랫폼의 구현 및 검증 자료를 포함합니다.

| 디렉터리 | 주요 내용 |
| --- | --- |
| `src/` | 초기 GPS·교통 데이터 처리, 이동수단 분류 및 통합 로직 |
| `scripts/` | 데이터 수집·전처리·평가 스크립트 |
| `tests/` | 기존 기능의 단위·통합 테스트 |
| `schemas/`, `config/` | 초기 데이터 계약 및 설정 |
| `reports/` | 모델 평가, 실험 결과 및 검증 기록 |
| `data/`, `mock/` | 보존된 참조 데이터 및 테스트·데모 자료 |
| `assets/` | 초기 UI 및 디자인 리소스 |

자세한 과거 구현과 실험 내용은 [초기 데이터 플랫폼 README](original-data-platform/README.md)를 참고하세요.

## 현재 프로젝트와의 관계

현재 CANOPY의 주요 애플리케이션과 데이터 파이프라인은 루트 저장소의 `apps/`, `ml/`, `cloud/`, `shared/` 등을 중심으로 관리합니다.

Legacy는 과거 구현을 보존하는 영역이지만, 일부 모듈은 현재 Databricks 코드에서 참조 가능한 호환 경로로 남아 있습니다. 따라서 모든 Legacy 코드를 사용하지 않는 코드로 간주하지 않습니다.

Legacy 내부의 실험 결과와 문서는 해당 개발 시점의 기록이며, 현재 서비스의 최종 구현 상태나 운영 성능을 의미하지 않습니다.

## 유지보수 원칙

- Legacy에서는 원칙적으로 신규 기능을 개발하지 않습니다.
- 기존 코드를 활성 영역으로 이전할 때는 대상 위치와 의존성을 먼저 확인합니다.
- 이전 과정에서 import 경로와 관련 테스트를 함께 정리합니다.
- 기존 실험 결과는 데이터셋, 평가 조건 및 개발 시점을 구분하여 해석합니다.
- 코드나 결과물을 제거할 때는 현재 참조 여부와 이력 보존 필요성을 검토합니다.

## 공개 사본 안내

이 저장소는 포트폴리오 공개를 위해 정리한 사본입니다. 일부 외부 원천 데이터, 학습 자료 및 모델 파일은 이용 조건과 공개 범위를 고려하여 제외되어 있습니다.

따라서 과거 코드가 참조하는 모든 파일이 현재 저장소에 포함되어 있거나, 이전 실험을 그대로 재현할 수 있는 것은 아닙니다.

자세한 사항은 [공개 사본 안내](../docs/PUBLIC_EDITION.md), [데이터 출처 및 이용 조건](../DATA_SOURCES.md)을 참고하세요.
